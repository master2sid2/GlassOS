# fs — files

Relative paths are counted from the user's home folder (`/home/name`), **not from the folder the program was started in**. `sys.user()` returns the home path itself. The program's own folder can be learned from `arg[0]`.

On failure the functions return `nil` and an error message. The functions read and write a whole file.

## Functions

### fs.read(path) → data | nil, err

The file contents as a string. Binary data is read unchanged. If the file does not fit into free memory, the error `not enough memory` is returned.

### fs.write(path, data) → true | nil, err

Creates or completely overwrites a file. The folder must exist. The data may be binary.

### fs.append(path, data) → true | nil, err

Appends to the end of a file.

### fs.volumes() → list

The mounted disks. Each has `name`, `path`, `kind` (`"FAT32"`, `"exFAT"`…), `used` and `total` in bytes, `memory` (an in-memory volume), `removable`, `network`.

```lua
for _, v in ipairs(fs.volumes()) do
  print(v.name, sys.size(v.used) .. " of " .. sys.size(v.total))
end
```

### fs.list([path]) → entries | nil, err

The contents of a folder, the home folder by default. The order is not guaranteed. Each entry is a table:

| Field | Meaning |
|---|---|
| `name` | The name |
| `dir` | `true` for a folder |
| `size` | The file size in bytes; for a folder — the number of entries |

```lua
for _, e in ipairs(fs.list("/apps")) do
  print(e.name, e.dir and "folder" or e.size)
end
```

### fs.exists(path) → boolean

`true` for both a file and a folder.

### fs.isdir(path) → boolean

### fs.mkdir(path) → true | nil, err

Creates one folder; the parent must exist. If the folder already exists, the error `already exists` is returned.

### fs.remove(path) → true | nil, err

Deletes a file or a folder. **A folder is deleted together with all its contents, without confirmation and without a recycle bin.**

### fs.rename(from, to) → true | nil, err

Renames or moves a file or a folder within one disk. Between disks use `fs.copy` and `fs.remove`.

### fs.copy(from, to) → true | nil, err

Copies a file, including from disk to disk and to a network folder. Does not copy folders.

## Where things are

| Folder | Purpose |
|---|---|
| `/home/name` | The user's files |
| `/home/name/Desktop` | The desktop |
| `/apps` | Programs from the system menu |
| `/media/...` | USB sticks and network folders |
| `/network/...` | The network neighbourhood, read only |
| `/tmp` | Temporary files, shared by everyone |
| `/system` | System settings; closed to programs |

`/network` is a list of neighbours, not real files: `/network/group/computer/folder`. `fs.list` returns what is already known and does not wait for the network: discovery runs in the background, so the first answer may be empty. Folder contents are not available here: to read files, mount the folder in Files, then it appears in `/media`.

```lua
for _, group in ipairs(fs.list("/network")) do
  print(group.name)
  for _, pc in ipairs(fs.list("/network/" .. group.name)) do
    print("  " .. pc.name)
  end
end
```

Keep the program's settings in the home folder as an ordinary text file: a relative path is enough, for example `fs.write("myapp.cfg", text)`.

## What a program may access

A program runs on behalf of the logged-in user, but it does not see everything the user sees:

| Place | Read | Write |
|---|---|---|
| The home folder, except `.config` | yes | yes |
| `/tmp` | yes | yes |
| The program's own folder, `/apps`, `/bin` | yes | no |
| `/network` | yes | no |
| A file chosen in `sys.open_file` or `sys.save_file` | yes | yes |
| A path from the start arguments | yes | yes |
| `/media`, `/system`, `.config`, other users' home folders | no | no |

A closed path returns the error `access denied`, and `fs.exists` and `fs.isdir` return `false`. To work with a file on a USB stick, ask the user to choose it in a dialog: access opens to that file only and only until the program ends. The home folder itself cannot be deleted or moved.

Saving to disk happens in the background, changes reach the disk within a few seconds.

When booted from an ISO, files live in memory and are lost at power-off (unless the boot USB stick keeps them, see the README).
